# Forest Geo Tools

Набор рабочих прототипов проекта ОМЕЛА для обогащения географических точек данными о рельефе, лесном покрове и почвах. Состояние на **24.11.2026**. На четырёх контрольных точках получены 4 из 7 запланированных характеристик. Общий вход, объединённый датасет и проверка перед массовой обработкой ещё в работе.

| Скрипт | Результат | Источник |
| --- | --- | --- |
| [`terrain_slope.py`](terrain_slope.py) | Высота в метрах и уклон в градусах. Мозаика DEM с заданной проекцией, `ee.Terrain.slope`, масштаб выборки 30 м | [Copernicus DEM GLO-30, 2024_1](https://developers.google.com/earth-engine/datasets/catalog/COPERNICUS_DEM_GLO30_2024_1) |
| [`forest_typology.py`](forest_typology.py) | Тип леса и максимальная нормированная оценка класса в точке. ForTy v1.0 за 2020 год, выборка 10 м | [Описание ForTy](https://pmc.ncbi.nlm.nih.gov/articles/PMC13686961/) |
| [`soils.py`](soils.py) | Код, название основного выдела почвенной карты и статус сопоставления | [ЕГРПР, карта 1:2 500 000](https://egrpr.esoil.ru/content/1DB.html) |

Ранее уклон рассчитывался по сетке 3×3 на основе высот SRTM через Open Topo Data. Текущий скрипт использует Copernicus DEM и Earth Engine. Copernicus DEM представляет высоту поверхности, включая растительность и сооружения.

## Запуск

Из корня репозитория, с [uv](https://docs.astral.sh/uv/concepts/projects/sync/) и Python 3.14 или новее согласно [`pyproject.toml`](pyproject.toml):

```bash
uv sync --locked
```

Скачайте архив `soil_map_M2_5-1.0.zip` и отдельную легенду `soil_map_M2_5_legend-1.0.xls`. Разместите их по структуре ниже. Храните `.shp`, `.dbf`, `.shx` и `.prj` вместе. [Страница загрузки ЕГРПР](https://egrpr.esoil.ru/content/1DB.html)

```text
data/soil/
  soil_map_M2_5_legend-1.0.xls
  soil_map_M2_5-1.0/
    soil_map_M2_5-1.0.shp
    soil_map_M2_5-1.0.dbf
    soil_map_M2_5-1.0.shx
    soil_map_M2_5-1.0.prj
```

```bash
uv run --locked python soils.py
```

Скрипт берёт встроенные точки в порядке `(id, lon, lat)` и перезаписывает `outputs/soils.csv`. Для запуска двух растровых модулей нужен аутентифицированный доступ к проекту Earth Engine, указанному в их `ee.Initialize`. При запуске из корня они пишут `terrain_slope.csv` и `forest_typology.csv` в корень. Сохранённые примеры этих таблиц лежат в `outputs/`. [Настройка Earth Engine для Python](https://developers.google.com/earth-engine/guides/python_install)

```bash
uv run --locked python terrain_slope.py
uv run --locked python forest_typology.py
```

## Почвенный модуль

`load_soil_data()` читает карту и легенду `.xls` через `calamine`. `soil_processing(points, soil_polygons, soil_legend)` создаёт точки EPSG:4326, выполняет левое пространственное объединение с `intersects` и расшифровывает `SOIL0` через `SOIL_ID`. Один полигон даёт код основного выдела. В легенде есть почвы, почвенные комплексы и непочвенные образования.

Выход содержит `id, lon, lat, soil_code, soil_name, soil_source, soil_scale, soil_status`. В памяти `soil_code` имеет тип `Int64` с поддержкой пропусков. CSV записывается без индекса, в UTF-8 с BOM. `soil_source` хранит URL, а `soil_scale = 2500000` — знаменатель масштаба карты.

- `ok` — у строки есть название и её ID встречается один раз.
- `no_data` — название отсутствует. Причину пропуска нужно выяснять по промежуточным данным.
- `ambiguous` — ID повторяется в выходе. Статус присваивается всем строкам этого ID и имеет приоритет над `no_data`. Кандидаты сохраняются отдельными строками.

## Перед массовой обработкой

Проверить точки на общей границе и в перекрытии полигонов, повторяющиеся входные ID, неверные или перепутанные координаты, отсутствующий и несовпадающий CRS, ошибки и пропуски при соединении с легендой. Масштаб карты ограничивает детализацию почвенного признака. Для ForTy `forest_score` — оценка выбранного класса по карте. Проверка на четырёх точках подтверждает работу прототипов на этих входах.

`points.py`, `validate_points.py`, `tree_species.py`, `phenology.py` и `merge_dataset.py` пока заготовки. Остаются единый список точек, породная группа, начало и конец вегетации, а также сборка и контроль итогового датасета.
